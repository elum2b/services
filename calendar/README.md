# Calendar service

Calendar хранит календари активности, шаги, прогресс пользователя и операции
получения наград. Сервис не начисляет награду во внешний баланс напрямую:
успешный `Record` атомарно сохраняет операцию и создает callback
`calendar.reward_granted`.

## Основной сценарий

Рекомендуемая последовательность вызовов:

1. `User.ListActive` — получить доступные в workspace календари.
2. `User.GetCalendar` — загрузить выбранный календарь, локализацию, шаги и
   видимые награды.
3. `User.GetProgress` — получить сохраненный прогресс пользователя. `nil`
   означает, что пользователь еще не получал награды этого календаря.
4. `User.Next` — при необходимости предварительно рассчитать доступность
   следующего шага. Метод ничего не записывает.
5. `User.Record` — зафиксировать попытку получения награды с уникальным
   `OperationID`.
6. При `status=granted` обновить экран по `RecordResult`, а фактическое
   начисление наград выполнить в обработчике `calendar.reward_granted`.

Пользователь однозначно определяется полной identity:
`WorkspaceID + AppID + PlatformID + PlatformUserID`. Один
`PlatformUserID` не является уникальным между приложениями и платформами.

## User.ListActive

Вызов:

```go
calendars, err := calendar.User.ListActive(ctx, user.ListActiveParams{
    WorkspaceID: workspaceID,
    Locale:      "ru",
    Now:         now,
})
```

Параметры:

| Поле | Обязательность | Значение |
| --- | --- | --- |
| `WorkspaceID` | Да | Канонический UUID workspace. |
| `Locale` | Нет | Локаль `title` и `description`. Если локализация отсутствует, строки будут пустыми. |
| `Now` | Нет | Момент проверки активности. Нулевое значение заменяется текущим временем UTC. |

Возвращает `[]ActiveCalendarModel`. В список попадают только активные,
неудаленные календари, для которых `start_at <= Now < end_at`. Отсутствующая
граница считается открытой.

Реакция клиента:

- пустой массив — не показывать календарный блок;
- один или несколько элементов — показать выбор/карточки календарей;
- ошибка — не заменять уже показанные данные пустым списком, обработать как
  ошибку загрузки.

## User.GetCalendar

Вызов:

```go
value, err := calendar.User.GetCalendar(ctx, user.GetCalendarParams{
    Identity: identity,
    Ref:      "daily_check_in",
    Locale:   "ru",
    Now:      now,
})
```

Параметры:

| Поле | Обязательность | Значение |
| --- | --- | --- |
| `Identity` | Да | Полная identity пользователя. |
| `Ref` | Да | UUID календаря либо стабильный `type`, например `daily_check_in`. |
| `Locale` | Нет | Требуемая локализация. |
| `Now` | Нет | Момент проверки активности; нулевое значение заменяется текущим временем UTC. |

Возвращает `CalendarModel`. Если календарь не найден, выключен, удален, еще
не начался или уже закончился, метод возвращает пустую модель с `id=""`.

Реакция клиента:

- `id=""` — убрать календарь с экрана или обновить `ListActive`;
- непустой `id` — отрисовать календарь;
- при `hide_future_rewards=true` использовать только пришедшие `steps`: сервис
  скрывает шаги дальше следующего доступного и клиент не должен угадывать
  скрытые награды;
- ошибка — сохранить прежнее состояние экрана и показать ошибку загрузки.

## User.GetProgress

Вызов:

```go
progress, err := calendar.User.GetProgress(ctx, user.GetProgressParams{
    Identity:   identity,
    CalendarID: calendarID,
})
```

Параметры:

| Поле | Обязательность | Значение |
| --- | --- | --- |
| `Identity` | Да | Полная identity пользователя. |
| `CalendarID` | Да | UUID календаря. В отличие от `CalendarRef`, здесь нужен именно ID. |

Возвращает `*ProgressModel`:

- `nil, nil` — сохраненного прогресса еще нет;
- непустая модель — использовать ее для выбранного календаря;
- ошибка — не обнулять локальный прогресс.

## User.Next

`Next` — read-only предпросмотр. Он рассчитывает результат по текущему
прогрессу так, как это сделал бы `Record`, но не создает операцию, не меняет
прогресс и не создает callback.

```go
preview, err := calendar.User.Next(ctx, user.NextParams{
    Identity:    identity,
    CalendarRef: "daily_check_in",
    Locale:      "ru",
    Now:         now,
})
```

| Поле | Обязательность | Значение |
| --- | --- | --- |
| `Identity` | Да | Полная identity пользователя. |
| `CalendarRef` | Да | UUID или `type` календаря. |
| `Locale` | Нет | Локализация возвращаемого календаря. |
| `Now` | Да для предсказуемого результата | Момент, на который рассчитывается доступность. Вызывающая сторона должна передать актуальное время. |

Реакция клиента определяется `status`, но даже при `granted=true` награда еще
не выдана. Для фактического получения всегда нужен `Record`.

## User.Record

`Record` — единственный пользовательский метод, который фиксирует попытку и
может выдать награды шага.

```go
result, err := calendar.User.Record(ctx, user.RecordParams{
    Identity:    identity,
    CalendarRef: "daily_check_in",
    OperationID: operationID,
    Now:         now,
})
```

| Поле | Обязательность | Значение |
| --- | --- | --- |
| `Identity` | Да | Полная identity пользователя. |
| `CalendarRef` | Да | UUID или `type` календаря. |
| `OperationID` | Да | Идемпотентный ключ длиной до 128 символов. Уникален в рамках календаря и полной identity. Повтор возвращает snapshot первой операции. |
| `Now` | Нет | Время операции; нулевое значение заменяется текущим временем UTC. |

Новый `OperationID` нужен для каждой новой пользовательской попытки. При
сетевом retry той же попытки необходимо повторить прежний `OperationID`.
Повтор не продвигает календарь и не создает второй callback.

## RecordResult

Пример успешного результата:

```json
{
  "operation_row_id": 501,
  "operation_id": "check-in:2026-07-28:user-123",
  "granted": true,
  "status": "granted",
  "calendar": {
    "id": "c7b6384e-e704-4a30-86c8-780bce907913",
    "type": "daily_check_in",
    "mode": "sequential_reset",
    "interval_type": "calendar",
    "interval_unit": "day",
    "interval_count": 1,
    "reset_after_intervals": 1,
    "end_behavior": "restart",
    "timezone": "Europe/Moscow",
    "hide_future_rewards": false,
    "is_active": true,
    "title": "",
    "description": "",
    "steps": [
      {
        "id": 73,
        "position": 3,
        "rewards": [
          {
            "key": "stars",
            "type": "quantity",
            "quantity": 200,
            "scale": 2
          }
        ]
      }
    ]
  },
  "position": 3,
  "rewards": [
    {
      "key": "stars",
      "type": "quantity",
      "quantity": 200,
      "scale": 2
    }
  ],
  "progress": {
    "current_position": 3,
    "claim_count": 3,
    "last_claim_position": 3,
    "last_claim_at": "2026-07-28T09:00:00Z",
    "next_claim_at": "2026-07-28T21:00:00Z",
    "is_completed": false,
    "reset_count": 0,
    "last_was_reset": false
  },
  "occurred_at": "2026-07-28T09:00:00Z"
}
```

Поля:

| Поле | Значение | Реакция |
| --- | --- | --- |
| `operation_row_id` | Внутренний неизменяемый ID сохраненной операции. Может отсутствовать у результата, который не был записан, включая `Next` и `not_found`. | Использовать для трассировки и дедупликации callback. |
| `operation_id` | Переданный ключ идемпотентности. У `Next` пустой. | Сопоставлять ответ с запросом; повторять прежний ключ только для retry той же попытки. |
| `granted` | `true`, если шаг успешно выдан. | Только при `true` считать получение подтвержденным Calendar. |
| `status` | Предметный результат попытки. | Обработать по таблице статусов ниже. |
| `calendar` | Snapshot определения календаря. | Обновить структуру календаря, но локализованные `title/description` после `Record` могут быть пустыми: `Record` не принимает `Locale`. Для текста сохранить модель из `GetCalendar`. |
| `position` | Позиция выданного шага. Отсутствует, если выдачи не было. | Выделить полученный шаг только при наличии поля. |
| `rewards` | Snapshot наград операции. | Показывать именно его; последующее изменение admin-настроек не меняет уже записанную операцию. |
| `progress` | Прогресс после попытки либо текущий прогресс, если выдачи не было. | Полностью заменить локальную модель прогресса. |
| `occurred_at` | Фактическое время расчета/записи. | Использовать для журналов и синхронизации, не как время следующей выдачи. |

## Статусы RecordResult

| `status` | Что означает | Как реагировать |
| --- | --- | --- |
| `granted` | Шаг выдан, прогресс сохранен, callback награды создан. | Показать награду, обновить прогресс. Баланс обновлять через результат внешнего обработчика наград или последующую синхронизацию. |
| `not_found` | Календарь по `CalendarRef` не найден или удален. | Убрать календарь и обновить список. |
| `inactive` | Календарь выключен администратором. | Не давать повторять попытку, скрыть календарь после обновления списка. |
| `not_started` | Календарь существует, но `start_at` еще не наступил. | Заблокировать кнопку до `progress.next_claim_at`. |
| `expired` | Наступил `end_at`. | Убрать активную кнопку и обновить список. |
| `not_available` | Следующая попытка пока недоступна по интервалу. | Показать таймер до `progress.next_claim_at`; не считать это ошибкой. |
| `completed` | Последовательность завершена при `end_behavior=stop`. | Показать завершенное состояние, кнопку получения скрыть. |
| `no_steps` | В активном календаре нет шагов. | Не показывать кнопку, записать диагностическое событие и сообщить владельцу конфигурации. |

Ошибка Go/transport не равна предметному статусу. При ошибке клиент не должен
считать награду выданной или самостоятельно менять прогресс. Безопасный retry
`Record` выполняется с тем же `OperationID`.

## CalendarModel

| Поле | Значение |
| --- | --- |
| `id` | UUID конкретного календаря. |
| `type` | Стабильный бизнес-ключ, например `daily_check_in`. Уникален внутри workspace и может использоваться как `CalendarRef`. |
| `mode` | Алгоритм выбора шага: `interval`, `sequential`, `sequential_reset`. |
| `interval_type` | Способ расчета границы: `calendar` или `floating`. |
| `interval_unit` | Единица интервала: `second`, `minute`, `hour`, `day`, `week`, `month`. |
| `interval_count` | Количество единиц в одном интервале. Значение по умолчанию при сохранении — `1`. |
| `reset_after_intervals` | Для `sequential_reset`: сколько дополнительных интервалов после момента следующей доступности допускается до сброса на первый шаг. Значение по умолчанию — `1`. |
| `end_behavior` | Поведение после последнего шага: `restart`, `repeat_last`, `stop`. |
| `timezone` | IANA timezone календарных границ, например `Europe/Moscow`; по умолчанию `UTC`. Публичные timestamps остаются в UTC. |
| `hide_future_rewards` | Скрывать шаги дальше следующего доступного в пользовательской выдаче. |
| `is_active` | Административный флаг активности. |
| `start_at` | Необязательное начало действия календаря. |
| `end_at` | Необязательная исключающая верхняя граница: при `Now >= end_at` календарь истек. |
| `title` | Заголовок выбранной локали. Может быть пустым при отсутствии локализации или в результате `Record`. |
| `description` | Описание выбранной локали. Может быть пустым. |
| `steps` | Шаги в порядке `position`. При `hide_future_rewards=true` массив может быть намеренно неполным. |

## Режимы и интервалы

### `mode`

| Значение | Поведение |
| --- | --- |
| `interval` | Позиция определяется абсолютным номером интервала от `start_at`, а при его отсутствии — от времени создания календаря. Пропуск интервалов может сразу перевести пользователя на более поздний шаг. |
| `sequential` | Каждая успешная попытка переводит пользователя на следующий шаг. Пропуск времени не сбрасывает позицию. |
| `sequential_reset` | Как `sequential`, но после превышения допустимого окна пропуска следующая успешная попытка начинается с первого шага и увеличивает `reset_count`. |

### `interval_type`

| Значение | Поведение |
| --- | --- |
| `calendar` | Доступность привязана к календарным границам в `timezone`: начало минуты, часа, дня, недели с понедельника или месяца. |
| `floating` | Следующая доступность отсчитывается от точного времени последнего получения. Например, `day/1` означает ровно сутки после `last_claim_at`. |

### `end_behavior`

| Значение | Поведение |
| --- | --- |
| `restart` | После последнего шага последовательность начинается с первого. |
| `repeat_last` | После последнего шага повторно выдается последний шаг. |
| `stop` | После последнего шага прогресс получает `is_completed=true`; новые попытки возвращают `completed`. |

## StepModel

| Поле | Значение |
| --- | --- |
| `id` | Технический ID шага внутри календаря. |
| `position` | Положительная уникальная позиция, определяющая порядок прохождения. |
| `rewards` | Награды этого шага. Пустой массив означает шаг без награды. |

## RewardModel

| Поле | Значение |
| --- | --- |
| `key` | Непрозрачный стабильный ключ ресурса, например `stars` или `lightning`. Его смысл определяет внешний обработчик наград. |
| `type` | `quantity` для количества или `duration` для временной награды. Пустое значение при admin-сохранении нормализуется в `quantity`. |
| `quantity` | Целое хранимое значение. Фактическое количество для дробной величины равно `quantity / 10^scale`. |
| `scale` | Число десятичных знаков. Например, `quantity=200, scale=2` означает `2.00`. Не делить на само значение `scale`. |
| `unit` | Только для `duration`: `second`, `minute`, `hour`, `day`, `week`, `month` или `year`. Для `quantity` отсутствует. |

## ProgressModel

| Поле | Значение | Использование |
| --- | --- | --- |
| `current_position` | Последняя успешно выданная позиция; `0`, если выдач еще не было. | Выделить текущий пройденный шаг. |
| `claim_count` | Общее число успешных выдач, включая повторы после `restart`/`repeat_last`. | Аналитика и счетчик; не использовать как индекс массива шагов. |
| `last_claim_position` | Позиция последней успешной выдачи. | Может отсутствовать до первой выдачи. |
| `last_claim_at` | Время последней успешной выдачи. | Может отсутствовать до первой выдачи. |
| `next_claim_at` | Ближайшее рассчитанное время следующей доступности или `start_at` для еще не начавшегося календаря. | Основа таймера; серверный `status` остается источником истины. |
| `is_completed` | Последовательность окончена при `end_behavior=stop`. | Скрыть кнопку получения. |
| `reset_count` | Сколько раз серия была сброшена режимом `sequential_reset`. | Аналитика/индикация серии. |
| `last_was_reset` | Последняя успешная выдача одновременно сбросила серию. | При `true` можно показать уведомление о начале серии заново. |

## ActiveCalendarModel

| Поле | Значение |
| --- | --- |
| `id` | UUID календаря. |
| `type` | Стабильный бизнес-ключ. |
| `mode` | Режим прохождения. |
| `title` | Локализованный заголовок или пустая строка. |
| `description` | Локализованное описание или пустая строка. |
| `is_active` | Для элементов этого списка всегда отражает активную конфигурацию. |
| `start_at` | Необязательное начало действия. |
| `end_at` | Необязательное окончание действия. |

## Callback calendar.reward_granted

Callback создается только для успешного `Record` с `status=granted`.

```json
{
  "operation_row_id": 501,
  "operation_id": "check-in:2026-07-28:user-123",
  "workspace_id": "4e11e7c3-9cdf-4ed1-9694-129db618124c",
  "calendar_id": "c7b6384e-e704-4a30-86c8-780bce907913",
  "app_id": 77,
  "platform_id": 88,
  "platform_user_id": "123",
  "position": 3,
  "rewards": [],
  "occurred_at": "2026-07-28T09:00:00Z"
}
```

| Поле | Значение |
| --- | --- |
| `operation_row_id` | Основной ключ дедупликации выдачи во внешней системе. |
| `operation_id` | Клиентский ключ идемпотентности исходного `Record`. |
| `workspace_id` | Workspace операции. |
| `calendar_id` | UUID календаря. |
| `app_id` | Приложение пользователя. |
| `platform_id` | Платформа пользователя. |
| `platform_user_id` | ID пользователя на платформе. Использовать только вместе с `app_id` и `platform_id`. |
| `position` | Выданная позиция. |
| `rewards` | Неизменяемый snapshot наград на момент операции. |
| `occurred_at` | Время успешного `Record`. |

Обработчик должен:

1. Идемпотентно применить `rewards`, используя `operation_row_id` как
   уникальный внешний ключ.
2. Определять пользователя по полной тройке
   `app_id + platform_id + platform_user_id` внутри `workspace_id`.
3. Возвращать `nil` только после успешного применения всех наград.
4. При временной ошибке возвращать ошибку: callback worker выполнит повтор,
   поэтому начисление обязано быть exactly-once на стороне потребителя.

## Admin-конфигурация

Основные поля `SaveCalendarParams` совпадают с `CalendarModel`, дополнительно:

| Поле | Значение |
| --- | --- |
| `WorkspaceID` | Workspace-владелец календаря. |
| `ID` | UUID. Для `CreateCalendar` может быть пустым — сервис сгенерирует ID; для `UpdateCalendar` обязателен. |
| `Type` | Обязательный уникальный бизнес-ключ внутри workspace. |

`SaveStepParams`:

| Поле | Значение |
| --- | --- |
| `WorkspaceID` | Workspace календаря. |
| `CalendarID` | UUID родительского календаря. |
| `ID` | ID шага; нужен для update, при create не передается. |
| `Position` | Положительная уникальная позиция внутри календаря. |

`SaveRewardParams`:

| Поле | Значение |
| --- | --- |
| `WorkspaceID` | Workspace календаря. |
| `CalendarID` | UUID календаря. |
| `StepID` | Родительский шаг. |
| `ID` | ID награды; нужен для update. |
| `Key`, `Type`, `Quantity`, `Scale`, `Unit` | Значения `RewardModel`. |
| `Position` | Порядок награды внутри шага. |

`SaveLocalizationParams`:

| Поле | Значение |

## Статистика и операции

`Admin.ListOperations` возвращает журнал всех попыток, включая неуспешные
предметные статусы.

| Поле | Значение |
| --- | --- |
| `id` | `operation_row_id`. |
| `app_id`, `platform_id`, `platform_user_id` | Полная identity пользователя без workspace, который задан параметром запроса. |
| `operation_id` | Ключ идемпотентности. |
| `granted` | Была ли выдана награда. |
| `status` | Предметный статус попытки. |
| `position` | Выданная позиция, если была. |
| `rewards` | Snapshot наград операции. |
| `current_position` | Позиция прогресса после операции. |
| `claim_count` | Число успешных выдач после операции. |
| `occurred_at` | Время операции. |

`StatsModel` и `DailyStatsModel`:

| Поле | Значение |
| --- | --- |
| `date` | UTC-дата дневного среза; есть только в `DailyStatsModel`. |
| `operation_count` | Число записанных попыток. |
| `grant_count` | Число успешных выдач. |
| `unique_users` | Число уникальных троек `app_id + platform_id + platform_user_id`. |

## Import и export

- формат пакета: `calendar.export.v1`;
- `ExportPackage.service` равен `calendar`;
- конфликт определяется по `calendar.type` внутри целевого workspace;
- стратегии импорта: `fail_on_conflict`, `skip_existing`,
  `update_existing`;
- `PreviewImport` валидирует пакет и возвращает `counts` и `conflicts`, но
  ничего не записывает;
- `Import` возвращает счетчики `imported` и `skipped`;
- пример готового пакета:
  [daily_check_in_import.json](examples/daily_check_in_import.json).
