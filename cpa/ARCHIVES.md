# Архивы CPA

Формат `cpa.export.v1` переносит каталог, персональные коды, назначения, исторические награды и события. Статистика пересчитывается из событий. Это перенос данных CPA, а не disaster-recovery backup PostgreSQL: очередь callback, история доставки, настройки и данные других сервисов не экспортируются.

## Импорт в работающий workspace

- `fail_on_conflict` отклоняет конфликтующий пакет до бизнес-записей.
- `skip_existing` оставляет существующие офферы и их runtime.
- `update_existing` заменяет каталог и незавершённый runtime. **Completed-назначения, их ID, код, награды и события сохраняются**, в том числе отсутствующие в архиве. Это правило имеет приоритет над входным snapshot.
- Если входное назначение уже завершено в target, его другой персональный код сохраняется как deleted, чтобы не допустить повторной выдачи этого кода.
- Исторические mode/source/shared code могут отличаться от текущего каталога. Валидируются собственный snapshot и связи истории.
- Сам импорт callback не создаёт. Первое завершение импортированного issued создаёт callback; completed не откатывается и не создаёт новое completion-событие. Старый pending callback сохраняет своё состояние и обычную доставку с тем же ключом.
- Complete, Issue, catalog mutations, статистика и import используют согласованные workspace locks. Записи импорта пакетные, в одной транзакции.

Доставка существующего outbox остаётся at-least-once: авария после внешнего начисления до ACK требует идемпотентности у получателя. Запрет повторного completion после импорта не является обещанием exactly-once сетевой доставки.

## Хранилище

Без настроек используется приватная папка `cpa/importexport` рядом с executable. Для монолита можно задать `ArchiveDirectory`. Несколько реплик должны использовать один S3 bucket/prefix либо общий файловый том; отдельные локальные диски не синхронизируются автоматически.

S3/MinIO подключается так:

```go
options := cpa.Options{
    ArchiveS3: &cpa.ArchiveS3Options{
        Bucket:          "service-archives",
        Region:          "us-east-1",
        Endpoint:        os.Getenv("CPA_S3_ENDPOINT"),
        Prefix:          "cpa/importexport/",
        UsePathStyle:    true, // MinIO
        AccessKeyID:     os.Getenv("CPA_S3_ACCESS_KEY"),
        SecretAccessKey: os.Getenv("CPA_S3_SECRET_KEY"),
    },
    ArchiveTimeout: 5 * time.Minute,
}
```

Для AWS можно оставить Endpoint пустым, выключить UsePathStyle и не передавать ключи: используется стандартная AWS credential provider chain. Bucket должен существовать. Startup проверяет HeadBucket с timeout 30s; для работы также нужны PutObject, GetObject, DeleteObject и ListObjectsV2. Prefix должен быть выделен под архивы CPA, одинаков у всех его реплик и не использоваться для посторонних файлов.

`ArchiveS3` нельзя смешивать с `Archive`/`ArchiveDirectory`. Пользовательское `Archive` должно реализовывать `List(context.Context) ([]cpa.ArchiveInfo, error)` для восстановления orphan-файлов. Без S3 сохранён дисковый fallback; файлы не пишутся в PostgreSQL.

S3 adapter проверен HTTP-интеграционным тестом двух независимых SDK-клиентов. Доступ к реальному bucket, политика IAM и установленная версия MinIO требуют отдельной проверки в целевом окружении; в этой задаче credentials production не использовались.

## Ресурсы, retry и остановка

- По умолчанию `ArchiveTimeout=5m`, независимо от короткого QueryTimeout обычных методов. Контекст транзакции передаётся SQL-запросам и действительно отменяет их.
- `ArchiveMaxRows=100000`, `ArchiveMaxBytes=32 MiB`. Export проверяет объём строк PostgreSQL в том же snapshot до загрузки пакета, затем ограничивает JSON; прямой import проверяет бюджет до preflight/write. Эти параметры можно настроить явно.
- ZIP upload ограничен 100 MiB; архив содержит ровно один manifest и один JSON-документ. Проверяются фактический размер распаковки и CRC. Слишком большой пакет завершается ошибкой лимита, без частичной записи.
- ZIP строится в ограниченном временном файле с методом STORE, чтобы собственный сильно повторяющийся JSON не нарушал anti-bomb ratio при обратном импорте. JSON-пакет ограничен бюджетом, сжатый ZIP не накапливается в bytes.Buffer.
- Worker продлевает lease. Receipt создаётся вместе с бизнес-изменениями. Если результат COMMIT неизвестен, worker проверяет receipt; если бизнес-данные применены, он восстанавливает invalidation кэша и завершает job без повторного применения и без повторного чтения архива.
- Ошибки сериализации транзакций, deadlock и временная недоступность PostgreSQL повторяются с backoff. Обычные transient retries ограничены; подтверждение уже применённого импорта восстанавливается до успешного обновления статуса, вместо ложного failed.
- Staging-файлы приватны и защищены файловыми locks; sweep удаляет оставшиеся после завершения процесса файлы старше retention, пропуская живые writers/readers. Cleanup применяется и к окончательным unreferenced ZIP, и к `.archive-*`, и к spool-файлам.
- Все публичные архивные методы учитывают root context CPA. Download удерживает контекст до Close потока. Job DTO не содержит Options, ArchiveKey, LockedBy и LeaseToken; сообщения наружу не содержат raw infrastructure errors.

Существующие базы bootstrap-ятся без удаления данных. До включения нескольких реплик нужно перевести archive backend на общее хранилище; автоматического переноса уже сохранённых локальных архивов в S3 нет.
